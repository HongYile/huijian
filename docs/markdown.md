# 回笺 Markdown

回笺的消息正文（`desp`）默认按 Markdown 显示。语法以 **CommonMark + GitHub（GFM）** 为基础，再加几条推送场景常用的扩展。Mac、安卓、iPhone 和管理网页的显示效果一致；Bark 锁屏通知只能显示纯文本，会自动转换（见文末）。

> 服务端 0.6.0 起支持。解析统一在服务端完成（`server/md.go`），客户端按解析结果绘制，所以各端效果一样。连接旧服务端时，客户端退回自带的简单解析：标题、列表、引用、代码块、粗体、斜体、链接可以正常显示，表格和扩展语法显示为原文。

## 标准语法

| 写法 | 效果 |
|---|---|
| `# 标题` … `###### 标题` | 一到六级标题 |
| `**粗体**` `*斜体*` `~~删除线~~` `` `行内代码` `` | 文字样式，可以组合：`***粗斜体***` |
| `[文字](https://…)`，直接写 `https://…` | 链接；正文里的网址自动变成链接 |
| `- 项目` `* 项目` `1. 项目` | 列表，缩进两格或三格表示子列表；有序列表从写的第一个数字开始编号 |
| `- [x] 已完成` `- [ ] 待办` | 任务列表（只读的勾选框） |
| `> 引用` | 引用，可以嵌套 `> >` |
| ```` ```python ```` … ```` ``` ```` | 代码块，标注的语言显示在角上；长行可以左右滑动 |
| `---` | 分隔线 |
| 表格（见下） | 表头加粗；`:--` 左对齐、`:-:` 居中、`--:` 右对齐；太宽时可以左右滑动 |
| `正文[^1]` + `[^1]: 说明` | 脚注，说明集中显示在正文末尾 |

```markdown
| 模型 | val_loss | 用时 |
|:-----|---------:|:----:|
| base | 0.231 | 3h |
| **large** | **0.198** | 6h |
```

和标准不同、更适合推送的两点：

- **单个换行就是换行**（和聊天软件一样），不用在行尾加两个空格；空一行是新段落。
- **中文标点紧挨加粗符号也能加粗**：`**注意：**内容`、`**「结果」**很好` 按标准 CommonMark 不会加粗，回笺会。网址紧挨中文标点（`见：https://…。`）也能识别，结尾的标点不算进网址。

不支持、会原样显示的：HTML 标签（`<br>` 除外，它表示换行）、数学公式 `$…$`、Mermaid 图（写在代码块里会按代码显示）、`{#id}` 之类的属性。

注意：按标准，`x**2 + y**2` 中间那段会被加粗。正文里写公式、通配符时放进反引号：`` `x**2 + y**2` ``。

## 回笺扩展

扩展都借用标准 Markdown 的图片、链接和引用写法，所以在别的 Markdown 查看器里也能看懂，不会乱码。

### 正文里显示附件：`attachment:`

和消息一起上传的附件（`file` 字段）可以在正文里引用，按**文件名**或**序号**（第一个附件是 1）：

```markdown
## 训练结果
![损失曲线](attachment:loss.png)
验证集上 val_loss 降到 **0.198**。

![](attachment:2)
完整报告见 [report.pdf](attachment:report.pdf)。
```

- `![说明](attachment:文件名)`：图片附件显示在正文的这个位置；不是图片的附件显示成一张附件卡片（文件名、大小，点开查看或下载）。
- `[文字](attachment:文件名)`：行内的附件链接，点开查看或下载。
- 文件名里有空格时写成 `![](<attachment:my file.png>)` 或 `![](attachment:my%20file.png)`。文件名先按完全一致匹配，再忽略大小写匹配。
- 图片写法找不到对应的附件时，这个位置显示「（找不到附件 xxx）」；链接写法找不到时只显示文字。
- 被引用的附件**仍然列在下方的附件区**，可以统一下载、保存、分享。

### 外部图片

`![说明](https://…/a.png)` 默认**不自动加载**，先显示成「点按加载图片」的占位卡片，点一下才去下载。这是为了不在打开消息时就向陌生服务器暴露你的 IP 和打开时间。需要一定显示的图片，请作为附件上传，再用 `attachment:` 引用。

### 进度条：`progress:`

```markdown
![训练进度](progress:15000/20000)
![下载](progress:42%)
![评估](progress:0.8)
```

显示成一条进度条，旁边写着「训练进度 75%（15000/20000）」。值可以写成 `已完成/总数`、`百分比%`，或 0 到 1 的小数（大于 1 的数字当百分比）。超出范围按 0% / 100% 显示。

### 提示框：`> [!类型]`

```markdown
> [!WARNING] 磁盘快满了
> /data 已用 95%，清理旧的 checkpoint。

> [!SUCCESS] 部署完成
> 版本 0.6.0 已上线。

> [!INFO]- 完整日志（默认折叠）
> ```
> step 15000 loss 0.198
> ```
```

| 类型 | 用途 | 图标 |
|---|---|---|
| `NOTE`（`INFO`） | 说明 | ℹ️ |
| `TIP`（`HINT`） | 建议 | 💡 |
| `IMPORTANT` | 重要 | ❗ |
| `WARNING`（`WARN`） | 警告 | ⚠️ |
| `CAUTION`（`DANGER`） | 危险操作 | ⛔ |
| `SUCCESS`（`DONE`） | 成功 | ✅ |
| `FAILURE`（`ERROR`、`FAIL`、`BUG`） | 失败 | ❌ |

- 类型不区分大小写；括号里是同义写法。不认识的类型按普通引用显示。
- `[!类型]` 后面的文字是标题，可以省略。
- 标题前加 `-`：**默认折叠**，点标题展开（适合放长日志）；加 `+`：默认展开，可以折叠。

### 跳到另一条消息：`huijian://message/<id>`

`[上一次的结果](huijian://message/123)`：在回笺里打开第 123 条消息（只能打开同一账号的消息）。

## 用法建议（写给发送消息的脚本和 AI）

- 标题（`text`）写结论，正文第一行写最关键的数字，锁屏通知只看得到前几行。
- 指标对比用表格，长日志放进折叠提示框 `> [!INFO]- 日志`，图表作为附件上传并在正文里用 `![](attachment:…)` 引用。
- 成功 / 失败用 `[!SUCCESS]` / `[!FAILURE]` 提示框，比单纯的 emoji 更醒目。
- 正文上限 64KB；结构特别复杂时（解析后超过约两万个元素、一行开头超过 16 层引用或列表、解析结果过大）整条按纯文本显示。

## 锁屏通知（Bark）里的样子

Bark 只能显示纯文本，转换规则：标题、段落保留文字；列表前加 `·` 或序号，任务列表用 ☑ / ☐；表格每行一条「列 · 列 · 列」；提示框显示「图标 标题」再接内容（没写标题时用类型名，如「⚠️ 警告」）；图片显示「🖼 说明」，附件「📎 名字」；进度条「训练进度 75%（15000/20000）」；代码块显示代码原文；脚注写成 `[1] 说明`。最多 300 字。

## 给客户端开发者：`doc` 结构

服务端 0.6.0 起（`/v1/info` 的功能 id `markdown.doc`），`GET /v1/messages`、`GET /v1/stream` 返回的每条消息（`type` 不是 `text` / `image` 且正文非空时）多两个字段：

- `preview`：纯文本预览（≤200 字，规则同上面的 Bark 转换），列表里的摘要直接用它。
- `doc`：`{"v": 1, "blocks": [块…]}`。`v` 升级时客户端如果不认识，退回自己解析 `desp`。

**块**（`type` 字段）：

| type | 字段 | 说明 |
|---|---|---|
| `heading` | `level` 1–6，`runs` | 标题 |
| `paragraph` | `runs` | 段落；`text` 里的 `\n` 是换行 |
| `list` | `ordered`、`start`（有序列表的起始数字，有序列表总是带，可能是 0）、`tight`、`items: [{check?, blocks}]` | `check` 为 true / false 表示任务列表项，没有就是普通项；`tight` 为 true 时项之间不留空 |
| `quote` | `blocks` | 引用，可以嵌套 |
| `callout` | `kind`（note / tip / important / warning / caution / success / failure）、`title`（纯文本，可能为空）、`fold`（空 = 不可折叠，`open`，`closed`）、`blocks` | 提示框 |
| `code` | `lang`（可能为空）、`text` | 代码块 |
| `rule` | — | 分隔线 |
| `table` | `align`（每列 "" / left / center / right）、`head: [runs…]`、`rows: [[runs…]…]` | 每个单元格是一组 runs；行的列数可能和表头不一致，按表头列数补齐或截断 |
| `image` | `att`（附件 id）或 `src`（外部 http(s) 地址），`alt`，附件时还有 `name`、`mime`、`size` | 附件图片直接显示；外部图片默认显示占位，点按后加载 |
| `file` | `att`、`name`、`mime`、`size`、`alt` | 非图片附件的卡片 |
| `progress` | `value`（0–1）、`label`、`text`（如 "15000/20000"，可能为空） | 进度条；显示文字 = label + 百分比 + （text） |
| `footnotes` | `items: [{n, blocks}]` | 脚注说明，放在正文末尾 |

**runs**（行内文字）：`[{text, b?, i?, s?, code?, href?, att?, fn?}]`，按顺序拼接。`b` 粗体、`i` 斜体、`s` 删除线、`code` 行内代码；`href` 是链接（只会是 http / https / mailto / huijian://，`huijian://message/<id>` 在应用内打开那条消息）；`att` 是附件链接（点开该附件）；`fn` 是脚注编号（显示成上标或 `[1]`）。

图片、附件卡片、进度条只出现在块级：段落里夹着图片时，服务端已经把段落从图片处拆开。表格单元格、标题里的图片降级为文字 `🖼 说明`。

客户端绘制要求（各端一致）：

- 所有块都要支持；未知 `type` 的块跳过，未知字段忽略。
- 表格和代码块横向可滚动、不撑破页面；代码块角上显示语言、有「复制」按钮。
- 文字可以选择和复制；**长按选择文字时不触发链接**，短按才打开。
- 外部图片默认不加载，点按后加载，请求不带任何登录凭据。
- 提示框没写标题时显示类型的中文名：说明 / 建议 / 重要 / 警告 / 危险 / 成功 / 失败（对应 note / tip / important / warning / caution / success / failure），前面是上面表格里的图标。
- 进度条文字 = `label` + 空格 + 百分比 + （`text`），百分比四舍六入五取偶取整（和服务端 Go `%.0f` 一致，12.5% 显示 12%）；`label` 为空时只显示百分比部分。
- 附件链接（runs 的 `att`）显示为「📎 文字」，点开同附件区（没下载就先下载）。
- `huijian://message/<id>` 指向本机没有缓存的消息时，提示「消息不存在或已被删除」，不单独向服务端请求。
- 正文里已经显示的附件图片，附件区照常列出（可以下载、保存、分享），但不必再显示一遍大图。
