# 架构与设计取舍

## 要解决的问题

跑实验、跑定时任务、跑爬虫时，需要随时知道进展。PushDeer、Server酱这类服务很方便，但有几个问题：
- 所有消息一样吵，分不出轻重：真正重要的只有"开始、结束、出错"，大部分是过程日志；
- 免费服务器发不了图，也发不了文件；
- 数据在别人手里，不能自己备份和检索。

回笺的目标是**自托管、分轻重、能带附件，发送和接收都保持"一个地址加一个 key"的轻量**。

## 组件

```
发送端（任何机器、脚本、容器、CI）
   curl / huijian CLI / Python SDK
        │  HTTPS  /message/push?pushkey=…
        ▼
┌─ HTTPS 反向代理（nginx / caddy）────────────────────┐
│ 只转发公开接口；限速；日志不记录 pushkey              │
└───────────────┬───────────────────────────────────┘
                ▼
┌─ huijian hub（单个 Go 二进制）──────────────────────┐
│ :8790 公网 API   发送 / 配对 / 长轮询 / 附件下载     │
│ :8791 管理后台   只在内网监听                         │
│ SQLite (WAL)    消息、设备、pushkey、会话             │
│ blobs/          附件，按 sha256 内容寻址，去重        │
└───────────────┬───────────────────────────────────┘
                ▼  长轮询 / SSE
接收端：Mac 菜单栏 App（原生 SwiftUI）
```

## 关键设计

### 1. 优先级 + 线程，解决"消息太吵"
- 每条消息都有 0–5 级优先级，客户端按级别决定要不要弹、要不要响。
- 同一 `thread`（例如一次训练）的消息在客户端里折叠成一行，详情里显示为时间线，进度类消息不会刷屏。

### 2. 推送只带文字，附件按需下载
- 推送通知只显示标题和摘要。附件在客户端里先显示为占位卡片（类型、文件名、大小），点击后才下载，显示进度条，完成后校验 sha256、生成缩略图，再用系统 QuickLook 查看原图、PDF、Word。
- 本地缓存默认 24 小时后自动清理，收藏的不清理；文字消息一直保留，直到用户删除（见下文第 6 点）。需要时重新下载即可。
- 服务端按 sha256 存储附件，同一个文件发多次只占一份空间。

### 3. 长轮询而不是长连接流
- 实测发现，部分杀毒软件（对 HTTPS 做中间人扫描的那类）和代理会缓冲流式响应，导致 SSE 完全收不到数据。
- 所以客户端默认用长轮询：`GET /v1/messages?since=<id>&wait=<秒>`。有新消息立即返回，否则等满后返回空列表，再发起下一次请求。
- 等待时长按所在网络自适应（0.6.4 起，最多 10 分钟，规则见 [api.md](api.md)）：手机网络每小时被唤醒的次数从约 72 次降到十几次，更省电；被运营商 NAT 或代理断开时自动调短。
- 每个响应都是完整结束的，任何中间设备都挡不住；延迟和 SSE 相同，基本在 1 秒以内。

### 4. 不丢、不重
- 发送端（CLI/SDK）发送失败时把消息写入本地 outbox，服务恢复后自动补发。
- 多个进程同时补发时，用原子改名认领任务；服务端再用幂等键 `idem` 去重。

### 5. 三个平面分离
| 平面 | 能做什么 | 暴露范围 |
|---|---|---|
| 消息平面 | 发送、接收、下载附件 | 公网（HTTPS） |
| 文件平面 | 附件下载 | 公网，但需要设备 token 加不可猜测的 128 位 ID |
| 管理平面 | pushkey、设备、会话管理 | 单独端口。默认对外开放（令牌登录 + 按 IP 限速），可以只绑本机走 SSH 隧道；中转部署时用 `HUIJIAN_ADMIN_DENY` 拒绝转发机本身的访问 |

### 6. 删除、归档、频道设置：一条变更流同步所有设备
- 删除是「从账号删除」：服务端删掉消息和附件文件，同账号的其他设备也要跟着删。归档状态（自动 / 已归档 / 保留在收件箱）和频道设置（显示名、隐藏、静音、置顶、顺序）同理，按账号保存。
- 服务端每做一次这类修改就往 `msg_changes` 表写一条变更（自增 `seq`），并唤醒这个账号挂起的长轮询。客户端长轮询时带上 `changes_since=<seq>`，新消息和变更在同一个响应里返回，不需要另开连接。
- 变更记录保留 90 天。客户端离线更久、或者服务端数据换过（新库、从备份恢复会更换「变更纪元」），服务端返回 `changes_reset`，客户端调用 `GET /v1/messages/state` 对账：本地有、服务端没有的消息才删除；纪元变了时只同步归档状态，不删本地消息，避免服务端重装后把本地历史清空。
- 自动归档（超过 N 天）在客户端按时间计算，不写服务端：天数是本机的偏好，每台设备可以不同。
- 隐藏 / 静音在服务端给消息标上 `silent`，所有设备（包括以后的手机端）都不响；客户端也按同样的规则兜底。

## 安全要点

| 风险 | 对策 |
|---|---|
| pushkey 泄露 | 每个发送方一把，可以单独吊销；按 key 限速；推荐用 POST 发送；nginx 示例配置不记录查询参数 |
| 附件被遍历 | 128 位随机 ID，必须带设备 token |
| XSS | 管理后台渲染 Markdown 前先整体转义 HTML，只允许 http/https 链接；严格的 CSP |
| CSRF | SameSite=Strict Cookie，POST 请求校验 Origin |
| SSRF | 服务端不替发送方抓取任何远程 URL，只接收上传 |
| 管理后台暴露 | 单独端口；登录需要 32 位随机令牌、"记住此浏览器"会话或一次性链接，按 IP 限速，会话可以逐个注销；可以只绑本机 |
| 明文 http | 公网 IP 直连时不加密，客户端配对时明确提示；有域名时建议 HTTPS 反向代理 |
| 更新包被篡改 | Ed25519 签名（私钥只在发布方）覆盖平台、构建号、版本、sha256、更新说明；客户端再校验代码签名证书 |
| 设备丢失 | 在管理后台吊销该设备的 token |
| 暴力猜测 | 无效 pushkey 或配对码会被延迟响应；配对接口严格限速 |

## 技术选型

| 组件 | 选型 | 理由 |
|---|---|---|
| 服务端 / CLI | Go | 单个静态二进制，交叉编译方便，内存占用约几十 MB |
| 数据库 | SQLite（`modernc.org/sqlite`，纯 Go） | 零运维、不需要 CGO，备份就是复制文件 |
| Mac 客户端 | Swift + SwiftUI | 原生体验；用 QuickLook 预览原图和 Office 文件；钥匙串存凭证 |
| 管理后台 | Go 模板 + 原生 CSS/JS | 不依赖任何外部 CDN 或前端框架 |
