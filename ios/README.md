# 回笺 iPhone 客户端（测试版 0.3）

SwiftUI 原生 App，用来在 iPhone 上看回笺的消息、附件和历史，并管理自己的账号：pushkey、设备、频道都能在手机上管，只用手机、不用 Mac 也能从注册到发出第一条消息。不上架 App Store，编出未签名的 IPA，用 GBox 等自签工具安装；锁屏提醒借用 App Store 的免费 App「Bark」。

## 为什么用 Bark

iOS 上，App 不在前台时能及时收到通知的唯一途径是苹果推送（APNs）。APNs 需要开发者账号给 App 配推送证书，而 GBox 用它自己的证书重签安装，重签后的 App 用不了 APNs；iOS 也不允许 App 在后台一直保持长连接。

所以分工是：

| 场景 | 谁负责 |
|---|---|
| 锁屏 / 后台的及时提醒 | 服务器收到消息后转发给 **Bark**（App Store 免费 App，有自己的 APNs 通道）。P5 紧急用 `critical`（静音和勿扰下也响）、P4 用 `timeSensitive`、P3 用 `active`，P0–P2 不转发；按这台设备的接收规则过滤（静默的 key / 频道、正在别的设备上使用时不转发）。点 Bark 通知用 `huijian://message/<id>` 跳回回笺 |
| 看详情、Markdown、附件、历史 | 回笺 App |
| App 在前台 | 回笺自己长轮询，消息秒到 |
| App 在后台、没配 Bark | `BGAppRefreshTask` 尽力拉取（什么时候跑由系统决定，可能几十分钟到几小时一次），收到 P3 以上新消息发本地通知 |

配了 Bark 后回笺不再发本地通知，避免同一条消息提醒两次；应用角标仍然显示未读数。

本地通知的规则和安卓端一致：P5 每条单独通知（时效性 + 提示音）；P3 / P4 单独通知最多保留 6 条，再来就撤掉已有的单独通知、合并成一条「N 条新消息」，汇总还在时新消息继续并入；打开某条消息撤掉它的通知和汇总，「全部已读」撤掉全部。Bark 支持端到端加密（AES-CBC）：在回笺里生成 Key，在 Bark 的「加密设置」里填同样的 Key（IV 随每条推送发送，Bark 里不用填）。加密时提醒级别、频道名、跳转链接也都放在密文里，Bark 的服务器看不到消息内容。

## 安装和更新（GBox）

1. 在 iPhone 上安装 GBox，按它的说明导入签名证书。
2. 拿到 `Huijian-<版本>-<构建号>.ipa`：自己编译（见下文），或从服务器下载 `https://<你的服务器>/ios/Huijian-<版本>-<构建号>.ipa`。
3. 隔空投送到 iPhone，用 GBox 打开并签名安装。
4. 以后更新（0.2.1 起）：回笺发现新版本时首页会出现「可以更新了」，点进去（设置 →「关于」）点「下载并用 GBox 安装」。回笺会用登录凭证从服务器下载 `Huijian-<版本>-<构建号>.ipa`，校验 sha256 和发布签名（Ed25519，公钥在构建时写进 App），通过后弹出「打开方式」菜单，选 GBox，导入后在 GBox 里安装。校验不通过时报错，不会把文件交出去；服务器给的版本不比当前新时也拒绝（防降级）。临时安装包留到 App 下次启动时删除（交给 GBox 后不立刻删，免得 GBox 还没拷完）。
5. 备选：GBox 软件源 `https://<你的服务器>/ios/gbox.appsrc`（「关于」里折叠在「也可以用 GBox 软件源（可能有延迟）」下面，有地址和复制按钮）。GBox 刷新软件源不可靠，服务器上已经是新版本，GBox 里可能一天以上都还显示旧版本，所以只作备选。

服务器发布新版本：`./release.sh "更新说明"`，或手动 `huijian release -platform ios -key <私钥> -version 0.2.1 -build N -notes 说明 Huijian-0.2.1-N.ipa`（见 [../docs/api.md](../docs/api.md)）。签名用的私钥要和 App 里内置的公钥配对，release.sh 发布前会检查。

## 第一次使用

1. 打开回笺，填服务器地址（例如 `https://push.example.com`，局域网可以填 `http://192.168.1.10:8790`），用账号密码登录，或输入 6 位配对码（在已登录的设备上生成，3 分钟内有效）。允许通知。
2. 打开「设置 → 锁屏推送（Bark）」：
   1. 在 App Store 安装 Bark，打开它并允许通知；
   2. 在 Bark 首页复制推送地址（形如 `https://api.day.app/xxxx/`），粘贴到回笺；
   3. 可选：打开「端到端加密」，点「生成」得到 32 位 Key 和 16 位 IV；在 Bark 首页 →「加密设置」选 AES256、CBC、pkcs7，填入同样的 Key，点「完成」后回到 Bark 首页一次让设置生效；
   4. 点「保存」，再点「发送测试」，Bark 应该马上弹出「回笺测试」。
3. 在「设置 → 连接」里点「测试推送」：服务器给自己发一条 P4，Bark 会弹通知，回笺列表里也会出现。

需要服务端 0.5.7 以上（功能 `bark`、`ios.source`）；服务端较旧时 Bark 卡片会提示「需要更新服务端」，其余功能照常可用。

## 管理（设置 →「管理」）

和 Mac 客户端的「Pushkey」「账户」页、侧栏频道菜单对齐，所有设备同步：

- **Pushkey**：列表显示名称、key、最近使用时间、是否已吊销；右上角「+」新建（名称、可选自定义 key：16–64 位字母、数字、`_`、`-`，留空由服务器生成，也可以点「随机生成」）。点进一把 key 可以改名、复制、换 key（旧 key 立即失效，要二次确认）、设置这台手机怎么接收（提醒 / 静默 / 不接收）、看发送示例（浏览器 URL 和 curl，用当前服务器地址）、用这把 key 给自己发一条测试消息。左滑吊销，已吊销的左滑删除（服务端 0.5.2 起），都要二次确认。
- **账户与设备**：显示用户名；设置或修改用户名和密码（已有密码时需要当前密码；账号还没有密码时，只有开启了「允许管理」的设备能设置初始密码）。生成配对码：6 位数字、3 分钟倒计时，被用掉后显示「已被某设备使用」（服务端 0.5.6 起）。设备列表标出本机和在线的设备，点进去看配对记录，左滑移除其他设备（二次确认；没有「允许管理」的设备不能移除有管理权限的设备）。还可以给本机改名、查看本机有没有服务器管理权限。
- **频道**：置顶、其他、已隐藏分组显示。点「编辑」拖动排序（只在同一组里拖），右上角可以恢复按最近活跃排序；右滑置顶，左滑删除（服务器上这个频道的全部消息和附件，二次确认）；长按有和 Mac 一样的菜单（置顶、重命名、静音、隐藏、恢复排序、删除）；点进去改显示名、开关置顶 / 静音 / 隐藏。首页的频道标签也按同样的顺序排列。
- **注册**：服务端开放注册时，登录页多一个「注册」，用户名规则和服务端一致。

设置实时同步（服务端 0.6.1 起）：别的设备或管理后台改了 key、设备、账户（新建 / 改名 / 换 key / 吊销 key，设备加入 / 改名 / 移除、管理权限，用户名 / 密码），长轮询的变更里会带 `keys` / `devices` / `account`，回笺在后台重新拉取（连续多条合并成一次），打开着的 Pushkey、账户与设备页面立即显示新数据；本机被移除时按「登录失效」处理。

权限以服务端为准：没有权限或参数不对时直接显示服务端返回的说明（例如「当前密码不对」「这台设备有服务器管理权限，只能在「允许管理」的设备上或管理后台移除」）。服务端太旧、没有某个接口时显示「需要服务端 x 以上，更新服务端后可用」。

## 回笺 Markdown

正文按服务端 0.6.0 起下发的 `doc`（解析好的结构）绘制，和 Mac、安卓显示一致：标题、列表（任务勾选框、嵌套、有序列表起始号）、引用、代码块（语言角标、左右滑动、复制）、表格（列对齐、左右滑动；超过 200 行时先显示前 200 行，点「显示全部」再展开）、七种提示框（没写标题时显示类型名，可折叠的点标题展开）、进度条、脚注。正文里用 `attachment:` 引用的图片直接显示（点开大图，附件区只列文件、不再重复显示大图），其他附件显示成附件卡片，行内附件链接显示为「📎 文字」。外部图片默认不加载，点「点按加载图片」才下载（不带 Cookie 和登录凭据，超过 20 MB 不加载；跳转最多跟 5 次，https 跳到 http 会被拦截），加载后点图片在应用内全屏查看。`huijian://message/<id>` 在应用内打开那条消息，本机没有时提示「消息不存在或已被删除」；网页链接短按才打开，长按选字不会去请求网页。列表摘要用服务端的 `preview`。写法和结构见 [../docs/markdown.md](../docs/markdown.md)。

连接旧服务端（没有 `doc`）时退回自带的简单解析：标题、列表、引用、代码块、粗体、斜体、链接正常显示，表格和扩展语法显示为原文。

## 编译

需要 Xcode（用到 `swiftc`、`actool`、模拟器），不需要 Xcode 工程，也不需要开发者账号。

```bash
cd ios
./build.sh          # 真机：build/Huijian-<版本>-<构建号>.ipa（Payload/Huijian.app，ad-hoc 签名，GBox 安装时重签）
./build.sh sim      # 模拟器：build/sim/Huijian.app
```

- 部署目标 iOS 17，用当前 Xcode 的 SDK 编译（iOS 26 以上的系统上自动是新的界面材质）。
- 版本号在 `VERSION`，构建号默认是 git 提交数（必须随发布递增）。
- 可选 `build.local.env`（已被 .gitignore 忽略）：`DEFAULT_SERVER=https://push.example.com` 预填登录页的服务器地址。`PUBLIC_BUILD=1 ./build.sh` 忽略这个文件。
- 应用内更新的签名公钥：环境变量或 `build.local.env` 里的 `UPDATE_PUBKEY`（`huijian release-pubkey <私钥>` 的输出）；没设置时读 `../mac/build.local.env` 里的 `UPDATE_PUBKEY`（和 Mac 端、release.sh 用同一套发布密钥）。构建时没有公钥的 App 不提供应用内下载，只能用 GBox 软件源更新。
- 图标由 `tools/make_icon.swift` 生成到 `Resources/AppIcon.png`（和 Mac 图标同一图形，满版不透明，圆角由系统裁切）。

## 代码结构

| 文件 | 内容 |
|---|---|
| `Sources/App.swift` | 入口、AppDelegate（注册后台刷新任务、通知点击）、根视图 |
| `Sources/AppModel.swift` | 全局状态：消息、已读、连接状态、长轮询循环（退避 5→120 秒、网络变化立即重连）、补拉、删除 / 归档同步、写盘、后台刷新、登录 / 退出、附件、Bark、更新检查 |
| `Sources/API.swift` | 设备接口（docs/api.md），错误处理（401 = 登录失效；纯文本 404 = 服务端较旧），附件下载与 sha256 校验，更新包下载；跨源跳转（协议、主机、端口任一不同）一律拒绝，登录凭证不会被带到别处 |
| `Sources/Store.swift` | 凭证（钥匙串 + 受保护的私有文件双写：GBox 换证书重签后钥匙串读不到也不掉登录）、设置、`messages.json`（最新 3000 条，不进备份；损坏时重新首次同步）、设备指纹 |
| `Sources/Notifier.swift` | 本地通知（按优先级设声音和中断级别，超过 6 条合并成汇总）、角标 |
| `Sources/MDDoc.swift` `DocView.swift` `MDSelfTest.swift` | 回笺 Markdown：服务端 `doc` 的模型、绘制和自检。**和 Mac 端（mac/Sources）内容完全相同**，改动时两边一起改 |
| `Sources/DocPlatform.swift` | 上面绘制代码的 iPhone 部分：字号、正文里的附件图片、附件卡片、剪贴板 |
| `Sources/Markdown.swift` | 连旧服务端时用的块级 Markdown 解析（和 Mac 端同一套规则），链接只放行 http / https / mailto |
| `Sources/Manage.swift` | 管理功能的数据模型、接口（pushkey、账户、设备、配对码、频道、注册）和规则（key、用户名、密码、频道排序，和服务端一致） |
| `Sources/ManageViews.swift` | 设置 →「管理」：Pushkey、账户与设备、频道 |
| `Sources/HomeView.swift` `DetailView.swift` `SettingsView.swift` `LoginView.swift` | 界面 |
| `Sources/Theme.swift` | 配色（和 Mac 端一致的宣纸底、靛青强调色，带深色模式）、优先级样式、时间格式 |
| `Sources/Updater.swift` | 应用内更新：安装包文件名、防降级、sha256 和 Ed25519 签名校验（与服务端 releaseMessage 一致）、每次下载一个临时子目录 |
| `Sources/UpdateShare.swift` | 校验通过后弹出系统「打开方式」菜单交给 GBox（没有能打开 .ipa 的 App 时退回系统分享面板） |
| `Sources/Demo.swift` `SelfTest.swift` | 演示模式和应用内自检 |

同步细节：

- 设备指纹 = `sha256("hongyan-ios:" + identifierForVendor)`，同一台手机重新登录沿用原来的设备记录；
- 第一次登录只拉最新 50 条并标为已读，之后按游标补拉（最多 20 页 × 200 条），补拉到的新消息照常提醒；
- 游标只在落盘成功后推进：写盘失败时这批消息照常提醒，但下次会重新拉到并补写，进程被杀也不会丢；
- 前台时长轮询 `GET /v1/messages?wait=50`（请求超时 70 秒）；切到后台立即取消，回到前台、网络恢复或切换时立即重连；出错按 5 → 120 秒退避；要求挂起却在 2 秒内空手返回时等 5 秒再发下一轮（防空转）；
- 其他设备的删除 / 归档：长轮询带 `changes_since`，第一次或游标作废（`changes_reset`、服务端数据纪元变化）时先 `GET /v1/messages/state` 对账；已归档的消息不进收件箱；
- 长轮询响应头 `X-Huijian-Latest-Build` 比当前构建号大时立即检查更新；
- 一次 401 不算登录失效（反向代理、强制门户也会返回 401），用 `GET /v1/me` 复核；判定失效后回到前台或下拉刷新会再复核。「重新登录」只丢掉凭证，同一服务器、同一设备登录后本地消息、已读、游标都保留；
- ATS 只开 `NSAllowsArbitraryLoads`（允许 `http://IP` 和 `http://域名`）。

## 还没做的

- 在 iPhone 上删除 / 归档单条消息（会同步其他设备的操作，但自己还不能发起）、按条件清理、查看归档、星标——这些目前在 Mac 客户端或管理后台操作；
- 一键进入管理后台、查看服务端存储和备份（管理后台一般只在内网开放）；
- iPad 布局（现在按 iPhone 布局运行）；
- 没在真机 + GBox 上验证过：模拟器只有 iOS 18.6，真机 IPA 只检查了包结构；时效性通知（P5）需要 time-sensitive 权限，重签后多半没有，会降级为普通通知。应用内下载更新后「打开方式」交给 GBox 这一步也只能在真机上验证（模拟器里只测了下载、校验和拒绝篡改）。
