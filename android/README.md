# 回笺 Android 客户端（测试版 0.3）

不依赖 Google 服务（FCM）和手机厂商推送：App 里常驻一个前台服务，和你自己的回笺服务器保持长轮询连接，有消息立即收到。

## 怎么收消息

| 接收方式 | 做法 | 消息延迟 | 耗电 |
|---|---|---|---|
| **实时（默认）** | 前台服务一直长轮询 `GET /v1/messages?wait=50`，有消息服务器立即返回 | 1 秒左右 | 和 ntfy 等自托管推送同一水平 |
| **定时检查** | 每 5 / 15 / 30 / 60 分钟用系统闹钟唤醒一次，拉一下就断开 | 约一个间隔（由系统安排，可能再晚几分钟） | 最低 |

两种方式都会在通知栏常驻一条「回笺 · 已连接」（安卓要求前台服务必须显示通知；它用的是最低打扰级别，不响不弹）。

可靠性措施（参考 ntfy、Gotify 的做法）：

- 重连等待、定时间隔、看门狗都用 `AlarmManager` 的 AllowWhileIdle 闹钟：手机进入 Doze 深度休眠也会按时触发（普通闹钟会被推迟到维护窗口，协程的 `delay()` 在睡眠时干脆不走）。加入电池优化白名单后系统允许用精确闹钟，不需要额外权限。没加白名单时只能用非精确闹钟，定时检查由系统安排，可能晚几分钟（模拟器实测 5 分钟间隔晚了约 4 分半），所以界面上写「下次约 08:54」；
- WakeLock 只护住「把请求发出去」这一小段：闹钟、重连时拿（带超时），长轮询请求一发出就放开，等待期间 CPU 可以睡（有数据到达时系统会唤醒）。实测每 50 秒一轮只持有几毫秒到两百毫秒；
- 看门狗每 10 分钟检查一次：长轮询超过 110 秒没返回（运营商 NAT 静默断开）就强制重连，等待到点没醒就强制唤醒，同步循环卡住就重启；
- Wi-Fi 和流量切换、断网后恢复时立即重连；
- 断线期间错过的消息，重连后按游标补拉，照常提醒（一次超过 8 条时只发一条汇总）；先写盘再推进游标，进程随时被杀也不会漏；
- 开机、App 更新后自动拉起服务；
- 多设备同步：长轮询带上变更游标，别的设备（或管理网页）删除、归档消息，改频道、pushkey、设备和账户时，挂起的请求立即返回，安卓随即更新（打开着的管理页也立刻刷新）；第一次、或服务端从备份恢复后先对账。定时检查模式在下一次检查时同步。

## 实测（Redmi K70，Android 16，HyperOS 3，公网域名）

| 场景 | 结果 |
|---|---|
| 亮屏、App 在前台 | P3 / P4 约 0.9 秒弹出通知 |
| 锁屏，省电策略为默认的「智能限制」 | **收不到**：HyperOS 在退到后台 5 秒后冻结 App（`frozen reason=tobg`），前台服务也不例外 |
| 锁屏，省电策略改为「无限制」 | 约 0.9 秒 |
| 模拟拔电、锁屏（系统进入轻度休眠） | P4、P5 约 1 秒 |
| 进程被杀，没开「自启动」 | 服务不会恢复，收不到 |
| 进程被杀，开了「自启动」 | 2 秒内自动拉起，0.9 秒收到 |
| 定时检查（每 5 分钟），锁屏 | 下一次检查时收到（约 285 秒，不超过一个间隔） |
| 锁屏连续一小时，每 10 分钟一条（其中 5 次处于 Doze 深度休眠） | 6 条全部收到，每条 0.7–0.8 秒 |

结论：**国产手机上必须做下面「后台运行检查」里的设置**，否则锁屏后收不到。

## 消息正文（Markdown）

连接服务端 0.6.0 及以上时，正文按服务端解析好的结构（消息里的 `doc` 字段）绘制，和 Mac、iPhone 效果一致：标题、列表（任务勾选框、嵌套）、引用、表格（可左右滑动；超过 200 行时先显示前 200 行）、代码块（可左右滑动、一键复制）、提示框（`> [!WARNING]`，可折叠）、进度条（`![训练进度](progress:15000/20000)`）、脚注（点上标跳到文末），以及用 `![](attachment:loss.png)` 嵌在正文里的附件图片（20MB 以内自动下载，点开看大图）和文件卡片。外部图片默认不加载，点按后才下载。文字可以长按选择复制；`huijian://message/<id>` 链接在应用内打开那条消息，返回时回到原来那条的阅读位置。长消息按需绘制，不会卡顿。写法见 [docs/markdown.md](../docs/markdown.md)。

连接旧服务端时退回自带的简单解析（标题、列表、引用、代码块、粗体、斜体、链接）。

## 管理账号（设置 → 管理）

只用手机也能完整管理自己的账号，和 Mac 客户端功能一致，改动所有设备共用：

| 页面 | 能做什么 |
|---|---|
| **Pushkey** | 列表（名称、key、最近使用时间、是否已吊销）；新建（名称，可选自定义 key：16–64 位字母、数字、`_`、`-`，留空自动生成）；改名、换 key（旧 key 立即失效）、吊销、删除已吊销的；复制 key；发送示例（浏览器地址和 curl，用当前服务器地址）并能给自己发一条测试；每把 key 在本机「提醒 / 静默 / 不接收」 |
| **账户与设备** | 用户名和密码（已有密码时需要当前密码，「允许管理」的设备可以直接重设）；生成配对码（3 分钟倒计时，被用掉后显示是哪台设备）；设备列表（标出本机和在线设备，可以移除其他设备，展开配对记录）；给本机改名；查看本机是否「允许管理」服务器 |
| **频道** | 改显示名、上移下移排序（置顶的在最前）、置顶、静音、隐藏、删除频道（服务器上这个频道的全部消息和附件） |

吊销、删除、移除设备、删除频道都要二次确认。没有权限的操作会显示服务端返回的说明；服务端太旧、没有某个接口时提示更新服务端。登录页在服务端开放注册时会出现「注册新账号」。

## 第一次使用

1. 从 [GitHub Releases](https://github.com/HongYile/huijian/releases) 下载 `huijian-android-*.apk`（`android-v*` 预发布）安装，打开回笺，填服务器地址（例如 `https://push.example.com`），用账号密码登录，或输入配对码（在已登录的设备上生成：手机「设置 → 账户与设备」，Mac 客户端点左下角头像 → 账户；3 分钟内有效）。服务端开放注册时也可以直接注册新账号。
2. 登录后会自动进入「设置 → 后台运行检查」，逐项点开：
   - **通知权限**：允许；
   - **不受电池优化限制**：小米 / 红米会跳到「电量详情 → 省电策略」，选**无限制**；
   - **自启动**：小米会跳到「自启动管理」，打开回笺；其他品牌按页面上的提示操作；
   - **P5 紧急消息穿透勿扰**（可选）：允许后，勿扰模式下 P5 也会响；
   - 最近任务里锁定回笺（防止一键清理）。
3. 点「测试推送」，几秒内应弹出通知。页面上的「最后一次和服务器通信」能看出连接是否正常。

## 通知

| 优先级 | 通知渠道 | 效果 |
|---|---|---|
| P5 紧急 | 「P5 紧急」 | 横幅 + 响铃 + 振动；授权后勿扰模式下也提醒 |
| P4 重要 | 「P4 重要」 | 横幅 + 响铃 |
| P3 普通 | 「P3 普通」 | 进通知栏，不出声 |
| P0–P2 | — | 不通知，只进列表 |

每一级都可以在系统的通知设置里单独调整。服务端标记为静默的消息（这把 key 设为静默、频道被静音或隐藏、你正在别的设备上使用）不提醒。

## 编译

在 Mac 上用命令行即可，不需要 Android Studio：

```bash
brew install --cask android-commandlinetools
brew install openjdk@21
export JAVA_HOME=$(brew --prefix openjdk@21)/libexec/openjdk.jdk/Contents/Home
sdkmanager --sdk_root=$HOME/Library/Android/sdk "platforms;android-36" "build-tools;36.0.0" "platform-tools"
echo "sdk.dir=$HOME/Library/Android/sdk" > local.properties
./gradlew assembleDebug                                   # app/build/outputs/apk/debug/app-debug.apk
./gradlew assembleDebug -PdefaultServer=https://push.example.com   # 登录页预填服务器地址
./gradlew testDebugUnitTest                               # 单元测试（doc 解析、附件下载、管理功能的解析和校验）
# 管理接口对真实服务端的集成测试（会增删 pushkey、设备、频道，只能指向测试用的服务端）：
HUIJIAN_IT_URL=http://127.0.0.1:18990 HUIJIAN_IT_TOKEN=DT_xxx ./gradlew testDebugUnitTest --tests '*ApiIntegrationTest*'
```

正式版签名：在 `android/signing.local.properties`（已被 git 忽略）里写一行 `signing=/path/to/release.properties`，那个文件里写 `storeFile`、`storePassword`、`keyAlias`、`keyPassword`，然后 `./gradlew assembleRelease`。没有这个文件时正式版不签名。

版本号在 `VERSION`，构建号默认取 git 提交数。

## 代码结构

| 文件 | 内容 |
|---|---|
| `SyncService.kt` | 前台服务：长轮询 / 定时检查、闹钟、看门狗、网络切换、WakeLock |
| `Api.kt` | 设备接口（OkHttp）：登录、配对、消息、附件下载与 sha256 校验、频道、pushkey |
| `Store.kt` | 设置、消息缓存（保留最新 3000 条）、token（Android Keystore 加密） |
| `Hub.kt` | 全局状态：消息、已读、连接状态、频道显示名 |
| `Manage.kt` | 管理功能的数据结构、解析和校验（pushkey、账户与设备、配对码、频道排序），规则和服务端一致 |
| `MdDoc.kt` | 解析服务端下发的回笺 Markdown 结构（`doc`），旧服务端退回 `Markdown.kt` |
| `Downloads.kt` | 附件下载（进程级）：同一附件同时只下载一份，各页面共用下载状态 |
| `Notifier.kt` | 按优先级的通知渠道 |
| `App.kt` | 开机自启、电池优化 / 自启动 / 勿扰设置入口（含各品牌自启动页面） |
| `ui/` | 登录（含注册）、消息列表、详情（`MdView.kt` 绘制正文，附件预览、看大图）、设置与后台运行检查、管理页（`KeysScreen.kt`、`AccountScreen.kt`、`ChannelsScreen.kt`） |
